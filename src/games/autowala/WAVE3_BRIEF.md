## Rules (non-negotiable)
- **Edit only the files you own** (listed in your brief). Anything else you need: put the exact request in your final report. You MAY create new files in your own area.
- Never run git commands that change the tree (no commit/stash/checkout/reset/clean). Never print secrets. No network calls from the game, no CDN, no external assets, no inline script/eval (hub CSP: `script-src 'self'`, `connect-src 'self'`).
- If a file you do not own fails to compile, someone is mid-edit: wait a minute and retry. Do not fix it.
- Tests: use the **PowerShell** tool (vitest fails in Git Bash here): `Set-Location A:\Coding\Projects\GameHub; npx vitest run src/games/autowala/<your area>`. Pure logic MUST have unit tests next to it (`*.test.js`), written to run fast (build shared fixtures once, never rebuild the whole city per test; tests time out at 5 s by default and the machine is loaded).
- **Performance is a requirement.** Per-frame work: no allocations in hot loops, no scene traversals, no `new Color/Vector3` per frame. New meshes: instanced, merged, <= a few hundred triangles each, culled by map tile (`render/chunks.js` `chunkedInstances`) when spread over the city; canvas textures <= 512 px, anisotropy <= 4; respect `ctx.gfx.cfg` (quality tier: `traffic`, `peds`, `drawDist`, `shadow`) and keep your whole system under ~0.5 ms per frame. Everything you create is disposed in `dispose`. Run on `low` quality too (software rendering picks it automatically).
- **The auto may drive on roads AND pavements** (pavement slab = 0.2 m step, `world.heightAt`). Only buildings, landmarks, metro pillars, trees, lamp posts and the lake are guardrails: they stop and slide the auto, never wreck it. Those contacts emit `crash` with `guard: true`: treat them as soft (no damage, no fine, no red flash; at most a small mood jolt). Only `crash` events WITHOUT `guard` (traffic, rage rams) are real crashes. `colliders.drivable(x,z)` is true anywhere that is not inside a solid or the lake. Markers/stops/checkpoints may sit on a pavement, but prefer roads for anything timed (a rule camera, a checkpoint, a race gate), because the player must be able to reach them without climbing a kerb at speed. Pavement spots: `colliders.inside(x,z,pad)`.
- Conventions: north is -z, heading 0 faces +z, steering right LOWERS the heading, India drives on the LEFT. Money only moves through `ctx.economy` (`add`, `spend`); every expense also `ctx.emit('expense', { kind, amount })`.
- Be defensive about other agents' pieces (they may be absent or empty while you work): `ctx.career?.`, `ctx.quests?.`, `ctx.rules?.`, `ctx.weather?.`, `ctx.fares?.`. Never throw from `update`.
- UI: neon Vice City style with the CSS variables in `ui/autowala.css`; every UI file has its own css (prefix `aw-<area>-`); Telugu next to English where it fits (`var(--aw-font-te)`); keyboard + gamepad + touch (44 px targets); respect `prefers-reduced-motion`. Menus use `ctx.openMenu(name)` / `ctx.closeMenu()` and render when `snap.menu === name`.
